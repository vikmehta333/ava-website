## 2. How content actually works (CRITICAL)
The site has **two kinds of pages**:
- **Custom full-HTML pages** (homepage, city pages, guides, answer pages): a complete `<!DOCTYPE html>…</html>` document with an embedded `<style>` block, dropped into the page content and **wrapped in a Gutenberg Custom HTML block**: `<!-- wp:html --> … <!-- /wp:html -->`. Dark navy + indigo design; they bring their own nav/footer.
- **Native posts** (older blog posts): plain content rendered by the theme's blog template (light content area + author/date meta bar).

**Pages vs Posts matters:** custom dark HTML must be a **PAGE, not a POST**. The post template wraps content in a white `.single-content-full` area + author/date meta bar, so dark-styled content becomes invisible. (We converted the Marketing Answers pages post→page to fix exactly this.)

## 3. Gotchas that WILL bite you
1. **wpautop mangling** — if full-HTML content is NOT wrapped in `<!-- wp:html -->`, WordPress injects `<p>`/`<br>` into your CSS and body → invisible headline, huge gaps. **Always wrap in the wp:html block.**
2. **Theme-chrome overlay** — the theme's sticky header + off-canvas menu render as a broken stacked overlay / white band on custom pages. **Fix:** add to the page's `<style>`:
   `#rs-header, .menu-ofcn, .menu-wrap-off, .nav-expander, #scrollUp, .rs-footer, footer.rs-footer { display:none !important; }`
3. **LiteSpeed object cache freezes writes** — intermittently a REST write returns 200 but does **not** persist (the `modified` timestamp doesn't advance). **Fix:** purge the object cache, then the page cache:
   `GET /?LSCWP_CTRL=PURGE&LSCWP_TYPE=object` (authed), then `…&LSCWP_TYPE=ALL`. If edits "won't save," this is almost always why.
4. **WAF blocks empty/short User-Agent** — REST/curl needs a browser-like UA or returns HTTP 406.
5. **Yoast fields over REST** — default REST only exposes `footnotes`. The installed mu-plugin **`ava-yoast-rest`** registers `_yoast_wpseo_title`, `_yoast_wpseo_metadesc`, `_yoast_wpseo_canonical`, `_yoast_wpseo_meta-robots-noindex`, etc. for REST read/write.
6. **Canonical domain** — `www` → non-www 301 is already in place; **non-www is canonical**. Don't "fix" it.
7. **Always visually verify** (Playwright render + screenshot) after publishing. HTML/API checks alone miss the theme-overlay class of bugs — this is how the 48-hour guide shipped broken.

## 4a. Light "Bright C" design system (the new standard)
- **Source of truth:** the **live homepage** (page id **23409**) — pull its raw content via REST (`?context=edit`) to copy the exact `<style>`, `<nav>`, `<footer>`, and Ask-Ava launcher. The old local `scratchpad/ava-home-C.html` does not survive across sessions; the live page does.
- **Tokens:** `--ink:#101828; --mut:#5b6472; --mut2:#6b7280; --bg:#f7f8fc; --panel:#fff; --line:#e6e8f0; --violet:#7c3aed; --cyan:#22d3ee; --pink:#ec4899`. Fonts: **Hanken Grotesk** (display h1/h2/h3) + **Public Sans** (body), via Google Fonts.
- **Anatomy:** sticky blur nav w/ CSS-only hamburger (`#nvt` checkbox + `.burger` label) · gradient-mesh hero (`.blob` b1/b2/b3) · `.pill` eyebrow · `.proof` stat strip · `.card`/`.grid3` feature cards w/ stroke-SVG `.ic` icons · `.steps` 01/02/03 · `.faq` native `<details>` accordion · dark `.ctaband` rhythm-break · shared `<footer>`.
- **CTA text is standardized site-wide to exactly "Get a free audit"** (→ `/contact/` or on-page `#cta`). Don't reintroduce "Book a Call" / "Get Started" / "Get Your Free Audit" variants.
- **Gotcha caught:** dark-band headings need an **explicit** `color:#fff` — inherited white loses to the theme's `h2` color rule (that's why the homepage CTA heading was once invisible).
- **Gotcha caught (media upload = multipart only):** uploading to `/wp/v2/media` with a **raw binary body** is blocked by **ModSecurity → HTTP 406 "Not Acceptable"**. Upload as **`multipart/form-data`** (a `file` field with filename + content-type) the way wp-admin does — that passes. (Used to put the 4 Reels in the media library.)
- **Gotcha caught (orphaned Elementor data):** creating a page via REST can land on a **recycled post ID that still carries another page's `_elementor_data`** (we hit this creating `/ai-use-cases/` — the ID had a dead "Fuel Me 340%" case-study layout). Elementor then renders its stale/empty builder and **discards your `wp:html` the_content** (symptoms: live page is ~140KB+, shows theme chrome, no light tokens — the QA checker flags it as `1:not-light`/`5:no-navcta`). **Fix:** clear the flags via REST (they ARE writable here): `POST /pages/<id> {"meta":{"_elementor_edit_mode":"","_elementor_data":"","_elementor_template_type":""}}`, purge, re-check. Always QA a newly-created page.
- **Gotcha caught (template):** a migrated page MUST have WP `template = elementor_canvas`. On the default template (`''`), the theme wraps your custom HTML in its header/menu/footer chrome (page balloons to ~200KB, menu injects `<a href="#">`). Fix via REST: `POST /pages/<id> {"template":"elementor_canvas"}`. The light template no longer carries the §3.2 chrome-hide rule because canvas needs none — but if you ever use a non-canvas template, add the hide rule back.
- **Service-page template + generator:** `scratchpad/gen_services.py` (template + icon lib) driven by `scratchpad/deploy_services.py` (per-page data → build → REST PUT → purge). Clone this pattern for city/guide/answer migration. Each page also ships **Service + FAQPage JSON-LD**.

## 9. Publishing cheat sheet
1. Build full-HTML content, wrapped in `<!-- wp:html --> … <!-- /wp:html -->`, including the theme-chrome hide rule (§3.2).
2. `POST /wp-json/wp/v2/pages` with `{title, slug, status:"publish", content, meta:{_yoast_wpseo_title, _yoast_wpseo_metadesc, _yoast_wpseo_canonical}}` (browser UA + Basic auth).
3. **Purge object cache, then page cache** (§3.3).
4. **Verify:** fetch the live URL AND Playwright-screenshot it (§3.7).
